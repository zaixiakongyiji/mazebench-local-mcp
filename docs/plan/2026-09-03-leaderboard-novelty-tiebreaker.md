# 排行榜引入棋盘新颖度（Novelty）平局判定设计

## 1. 背景与诉求
在评测智能体在 MazeBench 中的表现时，模型可能在达到步数上限（如 256 步）前仅探索了相同数量的房间（如 2 间），且收集宝石数均为 0。
在此种情况下，整局行动总步数均为 256 步。原规则仅通过 created_at DESC（创建时间从新到旧）进行平局仲裁，无法客观体现模型在探索质量、避免死循环与原地打转等维度的真实水平。

棋盘新颖度（Board-state Novelty）反映了智能体在近期步数中踏足未知格子与状态的比例（0%~100%）。当探索房间数相同时，新颖度更高的智能体表现出更好的探索活力。因此，需将该指标作为次级平局判定条件。

## 2. 详细改动设计

### 2.1 排序优先级调整
- **收集最多宝石榜 (GEMS COLLECTED)**：
  1. gem_count DESC（宝石数降序）
  2. oom_count DESC（房间数降序）
  3. 
ovelty DESC（**新增**：棋盘新颖度降序）
  4. 	urns ASC（行动步数升序）
  5. created_at DESC（创建时间倒序）

- **探索最多房间榜 (ROOMS VISITED)**：
  1. oom_count DESC（房间数降序）
  2. gem_count DESC（宝石数降序）
  3. 
ovelty DESC（**新增**：棋盘新颖度降序）
  4. 	urns ASC（行动步数升序）
  5. created_at DESC（创建时间倒序）

### 2.2 新颖度计算与缓存
- 从 run 目录中提取滑动窗口为 50 步的最近新颖度值，范围 0%~100%；
- 采用内存基于 runId 和文件 mtime 的轻量缓存，确保毫秒级极速响应；
- 在排行榜数据项输出中包含 novelty 字段。
